# SM90 MXFP4 MegaFlux Implementation Plan

> Execute each stage in order; the task's GPU acceptance gates take precedence
> over advancing to the next stage. Keep independent commits for accepted stages.

**Goal:** Add opt-in forward expert replication and W1/W2 overlap to SM90
MXFP4 MegaMoE without changing its numerical contract.

**Architecture:** Preserve the original drop and backend. Put maintained
executor code under `flashinfer/moe_ep/cute_dsl/megamoe/megaflux_sm90/` and
host-only Plan/oracle logic in a dependency-free module. Add a separate
backend/config only when the identity executor has a real execution path.
The Plan separates logical experts, owned experts, physical slots and active
slots; every block retains original source route identity.

**Tech Stack:** Python, CuTe DSL, existing Humming FP8 WGMMA projections,
NVSHMEM, torch.distributed, pytest; H200 EP8 via `ssh p2p-test-lrf` only.

## 1. Source mapping and baseline

Files: `docs/megaflux-sm90-bringup.md`, `docs/megaflux-results/`.

1. Verify remote `/root/flashinfer` checkout and relevant trees against local.
2. Run the existing independent single-rank oracle test.
3. Run EP8 oracle/reuse/Graph tests with isolated NVSHMEM bindings if needed.
4. Run target-shape benchmark with frozen geometry and persist complete output.
5. Record seeds, resolved tactic, GPU/dependency versions and limitations.
6. Commit accepted baseline; do not mix original-path failures with new code.

## 2. Plan ABI and CPU reference

Create `flashinfer/moe_ep/megaflux_plan.py` as a host-only leaf (no Torch/CUDA
or package re-export), and `tests/moe_ep/test_megaflux_plan.py`.

1. Define immutable configuration, block, replica and route records, status,
   epoch, layout and weight-version identity. Use explicit capacity failures.
2. Derive assignment capacity from per-source maximum tokens and top-k,
   block capacity from the smallest supported beta; bound all byte sizes by
   signed int64 before device allocation.
3. Build stable per-expert route lists in source/token/top-k order; only -1
   is a padding sentinel. Reject malformed IDs, dimensions and duplicate
   experts within a valid top-k row.
4. Partition expert rows once into beta blocks. Build owner-only assignment.
5. Implement four bounded load-only greedy candidates, deterministic ties,
   selected-maximum-preserving replica pruning and shared-expert refinement.
   Never cap a movement by donor overload. Keep forward free of gradient cost.
6. Materialize physical slots, separately aligned token/SF pool offsets,
   per-rank tasks and source return identities. Freeze geometry in the Plan.
7. Test random ragged source counts, masked routes, all empty, R=0/1/2/4,
   hot experts, exhausted slots, tails, capacity failures and determinism.
8. Run CPU tests in an isolated import process; acceptance establishes only
   the reference planner, not GPU execution.

## 3. Identity executor

Progress: corrected unpooled R=0 receiver lowering and expanded physical-slot
identity are validated on H200 EP8. The combined 13-case matrix covers R=0
and R=1/2/4 reserved capacity, fixed-Plan Graph, independent oracle and actual
executor-type assertions. Earlier pooled identity evidence is superseded.
See `docs/megaflux-identity-executor.md` and `docs/megaflux-physical-slots.md`.
This accepts the no-copy capacity gate, not replica transport or GPU planning.

Create maintained executor under `cute_dsl/megamoe/megaflux_sm90/` and a
separate opt-in backend beside `fp8_mxfp4_bf16_pull_cutedsl`.

1. Use only public drop exports; extend shim exports if required. Preserve
   all original vendored bytes and license headers.
2. Audit every owned-expert dimension and introduce separate slot capacity.
3. Make dispatch prep/publication/pull, scheduler, TMA weight slicing and
   return consume Plan descriptors. Keep no-dedup BF16 per-route return.
4. Reuse original GEMM, quantization and clamp semantics.
5. Validate R=0 exact route conservation and numerical tolerance on EP8;
   measure identity overhead and rerun original backend tests.
6. Do not begin weight replication before this gate passes.

## 4. Static synchronous replica

Accepted on H200: EP2 static 3 cases/rank and EP8 static + physical identity
12 cases/rank pass, including both full-leg byte comparisons, independent
oracle, repeated forward and expert reassignment in one slot. See
`docs/megaflux-static-replica.md`. Capture and overlap remain later stages.

1. Allocate fixed-stride owned+replica weight banks and stable descriptors.
2. Allocate symmetric export storage for all distinct exported experts,
   independently of receiver replica budget.
3. Copy complete W1 and W2 kernel-ready legs, confirm actual transfer
   completion, then execute one manually selected replica's full blocks.
4. Compare payload/offset/residual bytes, output, routing weight application,
   tails, empty sources and slot reassignment. Commit after EP8 acceptance.

## 5. GPU planner

Accepted on H200: 50 fieldwise device cases, EP2 4 online cases/rank,
EP8 14 online cases/rank, including changing routes, byte/numerical checks,
rank-0-only capacity failure and version-disagreement collective identity.
See `docs/megaflux-gpu-planner.md`. Serial control uses global scratch;
conservative synchronous export-root gets are charged overhead.

1. Stable local histogram and occurrence ordinals; exchange C[source,expert].
2. Implement oracle rules on GPU, including all four candidates and refinement.
3. Materialize Plan without host readback. Debug hashes must match across EP.
4. Agree collectively on identity fallback before any new-route dispatch.
5. Compare every Plan field to CPU oracle for varied M, budgets and overflow.

## 6. Weight pipeline

Accepted: EP2 19 and EP8 20 unique cases/rank (main + supplemental), plus
one device telemetry primitive test. E384/K6 execution, complete-leg bytes,
20ms W1/W2/offset/residual delays, same-Plan synchronous comparison, observed
FC1 progress during W2 delay, slot identities and global export retirement
pass. Native resource audit and logs: `docs/megaflux-w1-w2-pipeline.md`.

1. Separate epoch-qualified W1/W2 ready flags and per-chunk completion.
2. Add actual transfer completion and legal generic/async/TMA visibility.
3. Gate payload, offsets and residual reads before their first consumption.
4. Keep independent communication progress throughout persistent execution;
   recalculate barriers, registers, shared memory and resident clusters.
5. Inject W1/W2/scale delays and compare to synchronous execution of the SAME
   Plan. Require progress of FC1 during W2 delay and no early read/deadlock.

## 7. Epoch, Graph and benefit gate

1. Preallocate/JIT/warm all ranks before capture; keep addresses stable.
2. Retire old readers, transfers and returns before slot reuse; audit resets.
3. Stress Graph replay across plan/slot/expert/M changes and all padding.
4. Add optional GPU cost gate with charged planner/staging/transfer overhead.
5. Restore dedup/grouped return only after carrier DAG and actual-rank mask
   proofs; preserve switches for controlled comparisons.

## 8. Final evidence

1. Add backend enablement example and directly runnable test/benchmark entry.
2. Compare original, identity, fixed synchronous, fixed pipeline, online
   pipeline and gated pipeline using identical frozen settings.
3. Persist per-iteration rank-max latency; report p50/p95/p99, valid/padded M,
   beta, blocks/rank, replica count, transfer bytes and wait/planner costs.
4. Cover balanced small/large batches and legal skewed top-k; claim only
   measured results. Run relevant lint and repository self-review.
